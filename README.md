# Camera Share

カメラ共有プロジェクトです。**PCを常時起動するFlask方式から、同じWi-Fi内で端末同士が直接通信するWebRTC（P2P）方式へ移行する実験版**を追加しています。

## P2P版（PCサーバー不要）
GitHub PagesなどのHTTPS対応静的ホスティングに置いて利用する想定です。

- [送信サイト](p2p/sender.html)：送信端末1台。カメラ・マイクを開始し、管理端末用／公開端末用の接続コードをそれぞれ作成します。
- [管理サイト](p2p/admin.html)：送信端末の管理用コードを読み込み、回答コードを返すと映像・音声を受信します。管理者側で公開可否を切り替えます。
- [公開サイト](p2p/public.html)：送信側と管理側の両方で公開が許可されたメディアだけを受信します。

### 接続方法
1. 3ページをHTTPSで開き、3台とも同じWi-Fiに接続します。
2. 送信サイトでカメラ・マイクを開始します。
3. 送信サイトで管理用コードを作り、管理サイトに貼り付けます。管理サイトで回答コードを作り、送信サイトに戻して登録します。
4. 同じ手順を公開用コードでも行います。
5. 接続コードの交換は手動です。コードは接続相手以外に共有しないでください。

### 大事な制限
- P2P版は**試作段階**です。実機で接続・音声・公開切り替えを確認する必要があります。
- P2P版はメディアを中継するサーバーを使いませんが、接続コード交換も自動ではありません。
- 同じWi-Fiでも、ルーターの端末間通信禁止（AP isolation）などにより接続できないことがあります。
- ネットワークによってはSTUN/TURNなどの接続補助サーバーが必要です。現状の試作版はそれらを設定していません。
- カメラ・マイクの利用にはHTTPSが必要です。GitHub Pagesは静的ファイルの公開先として使えますが、映像を中継するわけではありません。
- インターネットを通じた不特定多数への公開や、機密性の高い映像・音声にはまだ使用しないでください。

## 旧Flask版
ルート直下の `server.py` と `static/` は旧方式です。これはPCまたはPython対応ホスティングでサーバーを動かす必要があります。P2P版とは別です。

映像・音声を送信・公開するときは、映る人・聞こえる人の同意を得てください。
