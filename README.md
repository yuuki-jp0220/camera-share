# Camera Share

PCを常時起動するFlask方式とは別に、**同じWi-Fi内で端末同士が映像・音声を直接送受信するWebRTC（P2P）版**を作成中です。

## P2P版（PCの中継サーバー不要）

GitHub PagesなどのHTTPS対応静的サイトにファイルを置いて使います。GitHub PagesはHTMLを配信するだけで、カメラ映像・音声の中継はしません。

| ページ | 役割 |
|---|---|
| [送信サイト](https://yuuki-jp0220.github.io/camera-share/p2p/sender.html) | 送信端末1台。カメラ・マイクを開始し、管理用と公開用の接続コードを作成 |
| [管理サイト](https://yuuki-jp0220.github.io/camera-share/p2p/admin.html) | 管理用コードを読み込み、回答コードを返して映像・音声を受信。public公開設定を操作 |
| [publicサイト](https://yuuki-jp0220.github.io/camera-share/p2p/public.html) | 送信側と管理側の両方で許可された映像・音声だけを表示 |

### 接続手順

1. GitHub PagesなどでリポジトリをHTTPS公開します。
2. 送信・管理・publicの3端末を同じWi-Fiに接続し、それぞれのページを開きます。
3. 送信サイトで「カメラ・マイクを開始」→「管理用コードを作成」。コードを管理サイトに貼り付けます。
4. 管理サイトで「回答コードを作成」。回答コードを送信サイトへ戻し、「管理端末の回答を登録」を押します。
5. 公開端末も同じ手順で「公開用コード」を交換します。
6. 管理サイトのpublic公開設定と、送信サイトの公開設定をそれぞれ操作します。

接続コードは接続相手にだけ渡してください。ページを再読み込みしたり送信を停止したりした場合は、接続を作り直す必要があります。

### 重要な制限・注意

- **試作版です。** 実際の端末で映像・音声・公開切り替えの動作確認が必要です。
- メディアを中継するPCやクラウドサーバーは使いません。接続コードの交換は手動です。
- 同じWi-Fiでも、ルーターの端末間通信禁止（AP isolation）やブラウザのネットワーク制限で接続できないことがあります。
- 現在はSTUN/TURNサーバーを設定していません。ネットワークによっては接続できません。別のWi-Fiやモバイル回線をまたいだ接続は想定していません。
- GitHub Pagesは静的ファイルをHTTPSで公開するために使えます。カメラ・マイク利用にはHTTPSが必要です。
- public側の公開OFFは受信側で表示を隠すだけではなく、送信側で該当トラックを無効化する試作制御です。厳密な配信停止・アクセス制御を保証する完成版ではありません。
- 接続コードを知っている人が接続を試せるため、個人情報や機密性の高い映像・音声には使用しないでください。
- 映像・音声に映る人、聞こえる人の同意を得てください。
